# deepseek-bridge — мост «браузер → локальный проект»

[![release](https://img.shields.io/github/v/release/maksyutoff90-bot/deepseek-bridge)](https://github.com/maksyutoff90-bot/deepseek-bridge/releases)
[![license](https://img.shields.io/github/license/maksyutoff90-bot/deepseek-bridge)](LICENSE)

> English version: [README.md](README.md)

Вы общаетесь с `chat.deepseek.com` в обычном Chrome/Edge, а расширение даёт
веб-чату доступ к файлам проекта (`E:\EnglishRus`) через локальный шлюз.

Работает в двух режимах:

* **инструменты** — модель пишет блок ` ```webcode ` с JSON-вызовом (`read`, `grep`, `run`…);
* **без команд** — модель просто присылает код обычным блоком, а мост сам
  сохраняет его в папку правок, если рядом указан путь к файлу.

Правки по умолчанию **не попадают в проект**: они складываются в
`E:\EnglishRus\_fixes\` с тем же деревом путей. Исходники меняются только после
кнопки «Применить».

```
 chat.deepseek.com  ──(DOM)──►  content.js  ──sendMessage──►  background.js
        ▲                                                         │
        │  результат в поле ввода                                 │ HTTP 127.0.0.1
        └──────────────  [webcode:result]  ◄──────────────────────┘
                                                                  │
                                                          gateway/server.mjs
                                                                  │
                                    E:\EnglishRus  ◄── apply ──  _fixes\
```

## Быстрый старт

1. **Шлюз**: двойной клик по `start-gateway.cmd` (окно оставить открытым).
   Он печатает адрес `http://127.0.0.1:8787` и токен (он же в `gateway\.token`).

2. **Расширение**: `chrome://extensions` → «Режим разработчика» → «Загрузить
   распакованное» → папка `extension` (или распакуйте zip из [Releases](https://github.com/maksyutoff90-bot/deepseek-bridge/releases)).

3. **Настройки расширения** (⚙ в панели): токен, порт `8787`.

4. Открыть `https://chat.deepseek.com` и вставить первым сообщением текст из
   [`SYSTEM_PROMPT.md`](SYSTEM_PROMPT.md).

5. Спросить про проект. Панель `WebCode` показывает, что выполнилось и сколько
   файлов лежит в `_fixes`. Кнопка **⇥** в шапке закрепляет панель справа на всю
   высоту, ширина меняется перетаскиванием левого края (состояние запоминается).

Проверить без DeepSeek: `http://127.0.0.1:8787/webcode-mock/chat.html`.

## Как попадают правки

### 1. Через инструмент

Модель вызывает `write` / `replace` — файл попадает в `_fixes`, а в ответе
приходит:

```
[webcode:result]
tool: write
ok: true
output:
staged: _fixes/englishrus/utils.py
original: englishrus/utils.py (не изменён)
lines: 214, было: 198
[/webcode:result]
```

### 2. Без специальных команд

Достаточно обычного ответа с кодом и путём рядом:

````
Исправил обработку:

**englishrus/utils.py**
```python
def normalize(text):
    ...
```
````

Путь ищется по заголовку/подписи перед блоком, по первой строке-комментарию
(`# src/app.py`) или по баннеру языка, если там указан файл. Совпадение языка и
расширения проверяется, блоки без пути игнорируются. Найденное сохраняется как
`_fixes/englishrus/utils.py`.

Приём можно выключить в настройках расширения («Сохранять код из обычных
ответов…»).

### 3. Применение

Кнопка **«Применить»** сначала показывает список: какие файлы изменятся и
насколько (`было → станет`, «новый»), и только после «Применить» / «Отмена»
что-то происходит. Дальше:

* копирует файлы из `_fixes` в проект;
* старый файл сохраняет в `_fixes/.meta/backup/<время>/`;
* **не трогает файл, если сохранённый кусок выглядит фрагментом** (меньше 30 %
  строк исходника) — такие пропуски панель показывает списком;
* список правок и история лежат в `_fixes/.meta/manifest.json`.

### 4. Кнопка «Записать» (вручную)

Если код пришёл обычным ответом и авто-захват не сработал (или просто хотите
контроля), нажмите **«Записать»** в панели: она возьмёт блоки кода из
последнего ответа, покажет их с путями (путь можно поправить прямо в поле) и
кнопку подтверждения. После «Записать» файлы перезаписываются в проекте,
старые версии уходят в `_fixes/.meta/backup/`. Если путь не угадан — поле
пустое, впишите его вручную.

Кнопка **«Папка»** открывает `_fixes` в проводнике.

### 5. Контекстное меню в дереве

ПКМ по файлу в дереве: **Открыть в VS Code**, **Показать diff** (сохранённая
правка против оригинала), **Прочитать** (предпросмотр в панели), **Скопировать
путь**, **Удалить в корзину** (`_fixes/.meta/trash`, файл можно вернуть).
ПКМ по папке — открыть её в проводнике или скопировать путь.

## Инструменты

| tool | args | Что делает |
|---|---|---|
| `list` | `path="."` | содержимое папки |
| `tree` | `path=".", depth=2` | дерево (глубина 1–5) |
| `read` | `path`, `startLine?`, `endLine?` | текст с номерами строк |
| `write` | `path`, `content` | сохранить файл (в `_fixes`) |
| `replace` | `path`, `old`, `new`, `all?` | точечная замена (в `_fixes`) |
| `capture` | `path`, `content` | принять готовый файл из ответа |
| `upload` | `path`, `contentBase64` | принять файл из проводника (до 2 МБ) |
| `staged` | — | список сохранённых правок |
| `apply` | `path?`, `force?` | перенести в проект (с бэкапом) |
| `reveal` | `path="_fixes"` | открыть папку в проводнике |
| `open` | `path`, `line?` | открыть файл в VS Code (на строке) |
| `diff` | `path` | сравнить правку с оригиналом в VS Code |
| `remove` | `path`, `permanent?` | удалить в корзину `_fixes/.meta/trash` |
| `grep` | `pattern`, `path="."`, `glob?`, `maxResults?` | поиск по регулярке |
| `run` | `command`, `cwd="."`, `timeoutMs?` | команда в оболочке (cmd/sh) |

Все пути резолвятся относительно корня; выход за корень (включая симлинки и
абсолютные пути) блокируется. `_fixes` исключена из `grep`/`tree`, чтобы
сохранённые копии не дублировали выдачу.

## Конфигурация — `gateway/config.json`

```json
{
  "root": "E:\\EnglishRus",
  "port": 8787,
  "token": "",
  "sandbox": true,
  "sandboxDir": "_fixes",
  "allowWrite": true,
  "allowRun": true,
  "runTimeoutMs": 30000,
  "mock": true
}
```

* `sandbox: true` — правки в `_fixes` (по умолчанию). `false` — писать напрямую.
* `sandboxDir` — имя папки правок.
* `allowWrite: false` — только чтение.
* `allowRun: false` — запрет команд (рекомендую для чужих проектов).
* `mock: true` — отдавать локальную заглушку чата для тестов.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| «нет связи со шлюзом», `Failed to fetch` | Шлюз не запущен — `start-gateway.cmd` |
| `401 неверный токен` | Токен в настройках ≠ `gateway\.token` |
| Панели нет, content script не внедряется | Chrome снял доступ к сайтам после обновления файлов: удалите расширение и загрузите заново (`Удалить` → `Загрузить распакованное`) |
| Блок `webcode` не выполняется | Модель не обернула вызов в ` ```webcode ` — повторите `SYSTEM_PROMPT.md` |
| Код из ответа не сохранился | Нет пути рядом с блоком или язык не совпал с расширением |
| Результат не ушёл в чат | Enter в поле ввода или автоотправка в настройках |

## История и переключение чатов

Мост работает только с **новыми** сообщениями:

* история, которая дорисовывается после открытия вкладки (DeepSeek — SPA, и в
  фоновой вкладке он может не рисовать чат вовсе), не выполняется и не
  сохраняется;
* после переключения чата в сайдбаре снимок берётся заново — старые блоки
  нового чата тоже не трогаются;
* отсчёт начинается с вашего первого действия в чате (ввод, вставка). Пока вы
  ничего не напечатали, панель показывает «жду вашего сообщения», даже если в
  чате уже есть код.

Отсюда правило: чтобы мост «взял» чат, просто начните в нём печатать.

## Безопасность

* **Токен** знает только расширение (service worker), страница его не видит.
  Шлюз слушает `127.0.0.1` и без токена не отвечает.
* **Песочница** снижает риск: модель может испортить только `_fixes`, проект
  меняется лишь после «Применить», и с бэкапом.
* **`run` — это настоящая оболочка** с вашими правами: она может изменить файлы
  в обход песочницы. `allowRun: false`, если не нужен.
* **Prompt injection**: модель читает файлы, и текст внутри может содержать
  инструкции. Для неё нет разницы между вашей просьбой и строкой в файле.
  Держите проект в git и просматривайте `_fixes` перед применением.
* Секреты (`.env`, ключи) сейчас **не** исключены из чтения — при работе с
  чужими проектами уберите их из корня или выключите `run`.

## Ограничения

* Путь к файлу в обычном ответе определяется эвристикой; блок без явного пути
  не сохраняется.
* Через `write` файл сохраняется целиком — это не патч с diff.
* Стриминг: блок обрабатывается, когда текст не менялся ~1.2 с.
* Автоотправка жмёт Enter синтетическим событием; если UI не принял — панель
  скажет «нажмите Enter».
* Один шлюз — один корень. Второй проект — второй шлюз на другом порту.
* Расширение `DSH PRO` работает на той же странице — отключите одно из двух.

## Проверка

```powershell
node tools\e2e.mjs
```

40 проверок: инструменты, песочница (write/replace/capture → `_fixes`),
`apply` с бэкапом и защитой от фрагментов, `sandbox:false`, защита путей и
токена, `background.js`, полный цикл в браузере (read → поле ввода, write →
`_fixes`, обычный код → `_fixes`, apply, run, drag&drop, ПКМ-меню,
закрепление панели, автоотправка) и скриншот.

Тест сам ставит расширение в чистый профиль через CDP
(`Extensions.loadUnpacked`), поэтому проверяется настоящий service worker.
