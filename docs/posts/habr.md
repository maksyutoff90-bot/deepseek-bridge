# Habr

Черновик статьи. Заголовок и лид можно менять под свою подачу.

## Заголовок

**Как я сделал мост между веб-чатом DeepSeek и локальным проектом — без API-ключа**

Альтернативы: «DeepSeek в браузере правит мой код: мост на расширении и локальном шлюзе»;
«Песочница, diff и бэкапы: как подружить веб-чат с локальным репозиторием».

## Лид

Хотелось пользоваться DeepSeek как обычным чатом — без ключей, балансов и SDK, — но
чтобы он видел мой проект и мог вносить правки. Получился небольшой мост: расширение
для Chrome плюс локальный шлюз на Node. Всё, что делает модель, сначала попадает в
папку `_fixes`, а проект меняется только после подтверждения и с бэкапом.

## Проблема

* Веб-чат не видит файлы, а копировать код туда-обратно руками — боль.
* API — это ключи, биллинг и другой продукт; хотелось остаться в привычном интерфейсе.
* Давать модели прямой доступ к диску страшно: одна ошибка — и файл перезаписан.

## Идея

Модель отвечает блоком кода с вызовом инструмента (`read`, `grep`, `write`, `run`…).
Расширение видит блок, отправляет вызов в локальный шлюз, забирает результат и вставляет
его в поле ввода. Дальше — Enter, и модель продолжает.

Ключевое решение — **песочница**: `write` и `replace` не трогают проект, а кладут
результат в `_fixes/<тот же путь>`. Применение — отдельным действием, с подтверждением,
бэкапом и защитой «короткий фрагмент не затирает большой файл».

## Архитектура

```
chat.deepseek.com → content.js → background.js → 127.0.0.1:8787 → файлы
```

* `content.js` — DOM-слой: находит блоки, показывает панель, вставляет результаты.
* `background.js` — единственное место сетевых запросов, поэтому CSP страницы не мешает.
* `gateway/server.mjs` — HTTP на loopback, токен, инструменты, песочница, манифест правок.
* `_fixes/` — зеркало проекта с сохранёнными правками, `_fixes/.meta` — история и бэкапы.

## Что умеет

* Инструменты: `list`, `tree`, `read`, `write`, `replace`, `grep`, `run`, `apply`, `diff`, `open`, `remove`.
* Захват обычного кода: если рядом с блоком есть путь — файл сохраняется автоматически.
* Ручная кнопка «Записать»: взять код из последнего ответа, поправить путь, подтвердить.
* Дерево проекта с drag & drop, контекстное меню (VS Code, diff, предпросмотр, корзина).
* Панель закрепляется справа и растягивается.
* История чата и переключение чатов не обрабатываются — ничего не выполняется повторно.

## Безопасность

* Токен знает только расширение, шлюз слушает `127.0.0.1`.
* Пути проверяются на выход за корень, включая симлинки.
* `run` — настоящая оболочка, её можно отключить в конфиге.
* Prompt injection реален: модель читает файлы, а в них может быть текст с инструкциями.
  Поэтому песочница, подтверждение и бэкапы — не украшение, а основа.

## Чего не умеет

* Расширение ставится распакованным (в Chrome Web Store пока не публиковалось).
* Правки — полная перезапись файла, без патчей по хункам.
* Один корень проекта на шлюз.

## Тесты

`node tools/e2e.mjs` — 40 проверок: инструменты, песочница, применение с бэкапом, защита
путей, service worker и полный цикл в браузере (read, write, захват кода, drag & drop,
контекстное меню, закрепление панели, автоотправка). Тест сам ставит расширение в чистый
профиль Chrome через CDP.

## P.S. для читателей

Инструмент автоматизирует веб-интерфейс, а не официальный API. Если DeepSeek изменит
вёрстку — сломается парсинг; это стоит держать в голове. И да, код, который вы
отправляете в чат, уходит в DeepSeek — как и при обычной вставке текста.
