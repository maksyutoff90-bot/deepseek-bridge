# Протокол обмена

Два канала: **страница ↔ service worker** (внутри расширения) и
**service worker ↔ шлюз** (HTTP на loopback). Страница никогда не ходит в шлюз
напрямую — так её CSP и CORS не мешают.

## 1. Страница → расширение

`content.js` использует `chrome.runtime.sendMessage`:

* `{ "type": "config" }` → `{ port, token, autoSend, capture, noAutoExpand }`
* `{ "type": "ping" }` → тело `GET /health` плюс `ok`
* `{ "type": "exec", "payload": { "tool": "...", "args": {...} } }` → тело
  `POST /exec` плюс `ms`, либо `{ "ok": false, "error": "..." }`
* `{ "type": "openOptions" }` → открыть настройки

## 2. Расширение → шлюз

`POST http://127.0.0.1:<port>/exec`, заголовок `X-Webcode-Token`.

```json
{ "tool": "read", "args": { "path": "main.py", "startLine": 1, "endLine": 40 } }
```

Успех:

```json
{ "ok": true, "tool": "read", "ms": 3, "path": "main.py", "lines": 1200, "shown": "1-40", "content": "   1| …" }
```

Запись в песочнице (`write`, `replace`, `capture`):

```json
{
  "ok": true, "tool": "write", "ms": 4,
  "staged": true,
  "path": "_fixes/englishrus/utils.py",
  "original": "englishrus/utils.py",
  "existed": true, "lines": 214, "beforeLines": 198,
  "note": "исходный файл не изменён — изменение лежит в папке исправлений"
}
```

`staged` — список ещё не применённых правок (последняя по каждому файлу;
применённые исключаются):

```json
{ "ok": true, "count": 2, "dir": "_fixes", "entries": [ { "original": "…", "staged": "…", "lines": 10, "beforeLines": 8, "at": "…" } ] }
```

`apply` — перенос в проект:

```json
{ "ok": true, "applied": 2, "files": [ { "path": "…", "backup": "_fixes/.meta/backup/<ts>/…" } ], "skipped": [] }
```

`skipped` заполняется, если сохранённый кусок похож на фрагмент (меньше 30 %
строк исходника) и `force: true` не передан.

`reveal` — открыть папку в проводнике.

Ошибки: HTTP 400 + `{ ok: false, error }` (инструмент/путь), 401 (токен),
400 со списком `tools` (неизвестный инструмент).

## 3. Блоки в ответе модели

**Инструменты** — `<pre><code class="language-webcode">` с JSON. Разбирается
первый объект/массив в тексте блока (устойчиво к баннеру «webcode / Copy»).

```json
{ "tool": "grep", "args": { "pattern": "TODO", "path": ".", "glob": "*.py" } }
```

**Без команд** — обычный блок кода, путь берётся из текста перед ним
(заголовок, `**путь**`, `Файл: …`), из первой строки-комментария или из баннера.
Язык блока сверяется с расширением (`python` ↔ `.py` и т.п.). Найденное
отправляется как `capture`, всегда в песочницу.

## 4. Результат обратно в чат

```
[webcode:result]
tool: read
ok: true
output:
   1| from __future__ import annotations
   2| …
[/webcode:result]
```

При ошибке — `ok: false` и `error: …`. Вывод обрезается до 6000 символов на
вызов; инструменты ограничивают чтение 400 КБ, вывод команд — 32 КБ.

## Инварианты

* Пути: `resolve(root, path)` и проверка, что результат внутри `root` (включая
  `realpath` для существующих путей).
* Песочница: целевой файл `_fixes/<rel>`, запись в саму `_fixes` запрещена.
* `apply`: бэкап в `_fixes/.meta/backup/<время>/`, манифест
  `_fixes/.meta/manifest.json`.
* Блоки, существовавшие на странице до загрузки расширения, не обрабатываются
  (защита от повторного выполнения при перезагрузке чата).
* Снимок берётся после «успокоения» страницы и до первого действия
  пользователя: всё, что отрисовано раньше (включая историю, дорисованную в
  фоновой вкладке), считается историей. После SPA-перехода между чатами снимок
  пересчитывается.
* Повторная отрисовка блока не приводит к повторному выполнению (хэш текста).
